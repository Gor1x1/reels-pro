# Банк ТЗ и модерация — как решения владельца учат агентов

Сценарий не попадает в съёмку сам. Путь такой:

```
исследование → сценарист пишет ТЗ → критик правит (один круг)
   → банк ТЗ → МОДЕРАТОР (человек) → принято → съёмка
                              ↓ отклонено с причиной
                     причина копится → агент учится
```

Смысл цепочки в последнем шаге. Отклонение без причины — потерянный урок;
отклонение с кодом причины — данные, из которых через месяц видно, что
именно агент делает не так.

## Банк ТЗ

Файл `sheets/tz-bank.csv`. Одна строка — одно ТЗ.

| Колонка | Что внутри |
|---|---|
| `id` | `M1-K1-ГЕЛ-001` — как в таблице |
| `дата` | когда написано |
| `товар` | артикул |
| `контур` | `А` категорийный · `Б` форматный · `В` звуковой |
| `формат` | из закрытого списка десяти |
| `хук` | первая фраза дословно |
| `боль` | id кластера + цитата |
| `референс` | ссылка на ролик-источник |
| `критик` | вердикт: принято / принято с оговорками |
| `статус` | `на модерации` · `принято` · `отклонено` · `отложено` |
| `причина_отказа` | код из справочника ниже |
| `комментарий` | что сказал владелец своими словами |
| `решено` | дата решения |

## Справочник причин отказа

**Код обязателен.** Свободный комментарий — сверх кода, не вместо.
Без кода статистика не собирается и агент не учится.

| Код | Значение | Что агент чинит |
|---|---|---|
| `не-та-боль` | боль не наша или притянута | строже отбор кластеров, поднять порог связи с товаром |
| `формат-не-лёг` | чужой приём не работает на нашем товаре | жёстче тест переносимости в контуре Б |
| `повтор` | уже снимали похожее | шире окно проверки в `dedup-check` |
| `запрет` | обещание нарушает `claims.md` | сверка с запретами до написания, не после |
| `слабый-хук` | первые полторы секунды не цепляют | больше вариантов у `hook-smith`, брать из банка хуков |
| `не-снять` | реквизит, локация или сложность не по силам | учитывать возможности креаторов при маршрутизации |
| `поздно` | формат уже на спаде | строже проверка свежести |
| `язык` | армянский неестественный, канцелярит | сверка со словарём фраз аудитории |
| `другое` | не подходит ни один код | комментарий обязателен, разбирается вручную |

## Правила модерации

1. **Решение принимает человек.** Агент не модерирует сам себя.
2. **Отклонение без кода не принимается** — бот не даст закрыть карточку,
   пока код не выбран.
3. **Отложено — не отказ.** Идея хорошая, момент не тот: возвращается
   в банк с датой пересмотра.
4. **Молчание сутки = отложено.** Конвейер не стоит в ожидании ответа.

## Как агент учится на отказах

Раз в неделю `trend-critic` и `zavod-scenarii` читают банк и считают
статистику по кодам. Правило поднятия:

- код встретился **3 раза за неделю** → это система, а не случайность;
- критик пишет наблюдение строкой `note` в `log.md` вики с адресатом
  и обязательным полем «что опровергнет»;
- профильный агент (`zavod-trendy` / `zavod-scenarii`) переносит
  подтверждённое правило в свой плейбук.

Пример: три отказа `формат-не-лёг` за неделю по контуру Б — значит, тест
переносимости слишком мягкий, и в него добавляется пункт.

**Обратная сторона тоже важна.** Что принимается без правок — тоже сигнал:
эти связки «контур + формат + тип хука» надо повторять. Считаются так же.

## Что смотреть владельцу раз в неделю

- доля принятых с первого раза — растёт ли;
- какой код лидирует — туда и вкладывать доработку;
- какой контур даёт больше принятых ТЗ, а какой — больше залётов
  после публикации (это разные вещи, и вторая важнее).
