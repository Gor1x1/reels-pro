# Reels Pro

Рабочий репозиторий: **`C:\Ferma\factory\reels-pro`**.
Ролик описывается спецификацией `src/spec.json`, стиль переключается одной строкой.

## Железные правила

1. **Сначала разбор, потом монтаж.** `pipeline/scan.py full` + просмотр кадров.
   Не резать вслепую — ни один таймкод не берётся из головы.
2. **Показать план по таймкодам** до сборки: из какого файла какой кусок и зачем.
3. **Эмодзи не использовать.** Они удешевляют картинку. Выключены во всех стилях.
4. **Проверять результат программно** — `pipeline/qc.py`, а не на глаз.
5. **Первые 1.5 секунды решают всё.** Заставки с логотипом в начале не ставить:
   они съедают ровно те секунды, на которых зритель решает листать или нет.

## Четыре режима

| Режим | Что на входе | Чем собирается |
|---|---|---|
| 1 · сборка из сцен | оживлённые клипы Seedance | сцены `clip` подряд, озвучка отдельной дорожкой |
| 2 · монтаж сырья | съёмка живого креатора | разбор речи, резка пауз, матирование фона |
| 3 · нарезка из готовых | банк чужих рилсов товара | куски из 3–5 файлов в один ролик по сценарию |
| 4 · доработка | готовый ролик | варианты, титры, уникализация |

Режим 3 — основной на старте: материал уже снят и стоит ноль.

## Сценарий на входе

Монтаж начинается не со спеки, а со **сценария от сценариста** —
`script.json`. Мост собирает из него и спеку, и субтитры:

```bash
python pipeline/script2spec.py runs/<дата>/<ID>/script.json
```

Формат: список битов, у каждого роль в сюжете, длительность, что должно
быть в кадре и реплика.

```jsonc
{
  "id": "M1-K1-ГЕЛ-001",
  "product": "гель-дюрин",
  "lang": "hy",
  "style": "fresh-mint",
  "pacing": "fast",
  "beats": [
    { "role": "hook", "sec": 2.6,
      "shot": "девушка замечает пятно на любимой майке, злится",
      "source": { "src": "src/a.mp4", "in": 1.0 },
      "onscreen": "ԲԻԾԸ ՉԻ ՀԵՌԱՆՈՒՄ" },

    { "role": "problem", "sec": 4.0,
      "shot": "бросает майку в мусор, потом достаёт обратно",
      "source": { "src": "src/b.mp4", "in": 3.0 },
      "line": "Այս բիծը երկու անգամ լվացի, ոչինչ չօգնեց։" }
  ]
}
```

| Поле бита | Что это |
|---|---|
| `role` | `hook` · `problem` · `solution` · `demo` · `proof` · `step` · `offer` · `compare` · `cta` |
| `sec` | сколько бит идёт |
| `shot` | что должно быть в кадре — по нему подбирается кусок материала |
| `source` | `{src, in}` — откуда берём. Сценарист может не заполнять |
| `line` | реплика: идёт в озвучку и в субтитры |
| `onscreen` | крупный титр на экране (у `cta` две строки через `\n`) |
| `overlays` | накладки, если сценарий их требует |

**Сценарист заполняет `role`, `sec`, `shot`, `line`.** Поле `source` —
работа монтажа: сначала `scan.py` разбирает материал, потом под каждый
`shot` подбирается кусок. Мост скажет, у каких битов источника не хватает,
и покажет, что там должно происходить по сценарию.

## Порядок работы

```bash
# 1. что в файлах: длительность, ориентация, паузы, чужие склейки, кадры
python pipeline/scan.py full <файлы...> --frames-dir runs/frames --every 1 --out runs/map.json

# 2. привести к общему знаменателю — иначе куски не стыкуются
python pipeline/prep.py shots <файлы...> --out public/src --fit crop

# 2а. горизонтальный исходник — кадрировать с трекингом, а не по центру
python pipeline/smartcrop.py wide.mp4 --out public/src/clip.mp4

# 2б. в кадре речь, текст реплики известен — выравниваем, а не распознаём
python pipeline/align.py clip.mp4 --script script.json --out src/captions.json

# 2в. текста нет (чужой ролик, съёмка без сценария) — расшифровка
python pipeline/transcribe.py clip.mp4 --lang ru --out src/captions.json

# 3. музыка под длину и настроение ролика
python pipeline/music.py --sec 28 --mood energetic --out public/music.mp3

# 4. написать src/spec.json и src/captions.json и проверить их ДО рендера
python pipeline/validate.py

# 5. собрать (обёртка сама подставляет пути и рабочий каталог)
.\build.ps1 -Out out\master.mp4 -Master

# 6. проверить числами, если собирали без -Master
python pipeline/qc.py out/master.mp4 --json runs/qc.json
```

**Шаг 4 не пропускать.** Рендер стоит минуты, а ошибка в таймкоде видна
только на готовом файле. Валидатор ловит главную ловушку сборки: кусок,
который выходит за конец исходника — на экране получится замерший кадр.

Запускать рендер только через `build.ps1`: Remotion ищет `public/` и точку
входа относительно рабочего каталога, и при вызове из другой папки все
файлы отдадут 404.

Кадры из шага 1 смотреть **глазами модели** — по ним выбирается, какой кусок
откуда брать. Это и есть монтаж: не «первые 4 секунды каждого файла», а те
куски, где происходит нужное сценарию действие.

## Спецификация

```jsonc
{
  "style": "fresh-mint",         // восемь стилей, таблица ниже
  "pacing": "fast",              // темп: calm | normal | fast | punch; не задан — из стиля
  "lang": "hy",                  // ru | hy | en — определяет шрифт
  "fps": 30,
  "platform": "multi",           // безопасные зоны; multi = видно на всех семи сетях
  "captionAnim": "word-pop",     // вид анимации субтитров, см. ниже
  "voice": "voice.wav",          // озвучка отдельной дорожкой
  "music": "music.mp3",
  "musicVolume": 0.08,
  "duck": true,                  // музыка приглушается под речь
  "sfx": [{ "src": "sfx/whoosh.mp3", "at": 2.6, "volume": 0.4 }],
  "scenes": [ ... ]
}
```

Длительность сцены задаётся в секундах (`sec`) или кадрах (`dur`).
Секунды надёжнее: сумма сцен должна равняться длине озвучки.

**Бренд задаётся только явно.** Поля `brand.badge` / `brand.badgeSrc` /
`brand.name` пустые — значит логотипа и титра с именем в кадре не будет.
Чужой логотип в ролике — брак, который заметят все, поэтому значений
по умолчанию здесь нет.

### Типы сцен

```jsonc
// хук: кадр из материала с титром поверх. Не заставка.
{ "type": "hook", "sec": 2.6, "src": "src/a.mp4", "isVideo": true, "in": 1.0,
  "title": "ԲԻԾԸ ՉԻ ՀԵՌԱՆՈՒՄ", "zooms": [[0, 1.0], [0.8, 1.12]] }

// кусок из файла — то, чем собирается ролик из нескольких источников
{ "type": "clip", "sec": 4.0, "src": "src/b.mp4", "in": 3.0,
  "enter": "whip", "speed": 1.0, "label": "ՓՈՐՁ",
  "zooms": [[0, 1.3]], "pan": [0, -0.14],   // сдвиг кадра вверх
  "mute": false, "volume": 0.5 }             // звук исходника поверх музыки

// до / после одним кадром: граница едет и открывает результат
{ "type": "compare", "sec": 4.0, "at": 0.9, "wipe": 1.1,
  "before": { "src": "src/b.mp4", "isVideo": true, "label": "ՄԻՆՉ" },
  "after":  { "src": "src/d.mp4", "isVideo": true, "label": "ՀԵՏՈ" } }

// говорящий на весь кадр (материал из spec.video)
{ "type": "speaker", "sec": 12, "zooms": [[0,1.04],[5.6,1.1]], "nameAt": 4.0 }

// вставка: видео или фото
{ "type": "broll", "sec": 3, "src": "screen.mp4", "isVideo": true, "label": "DEMO" }

// финал: призыв поверх работающего товара, а не поверх заставки
{ "type": "cta", "sec": 3, "src": "src/c.mp4", "isVideo": true, "in": 6.0,
  "line1": "ՊԱՏՎԻՐԻՐ", "line2": "ՀԻՄԱ" }
```

**У CTA всегда задавать `src`.** Статичная заставка в финале роняет
досмотр и ловится проверкой как замерший кадр: последние три секунды
должны жить. Картинка вместо клипа — запасной вариант, она едет наездом.

`in` — с какой секунды исходника берётся кусок. Резка происходит на рендере,
файлы не портятся, план правится в одну строку.

### Вход сцены

`enter`: `cut` (по умолчанию) · `fade` · `zoom` · `whip` · `slide`.
Резкая склейка честнее и держит темп. Переходы — там, где меняется место
или время действия, а не на каждой склейке подряд.

### Накладки

Появляются поверх сцены, `at` и `dur` — в секундах от начала сцены.

```jsonc
"overlays": [
  { "kind": "punch",   "at": 0.2, "dur": 2.4, "line1": "ՄԵԿ", "line2": "ԿԱԹԻԼ" },
  { "kind": "offer",   "at": 2.6, "dur": 2.4, "price": "2 900 ֏", "oldPrice": "4 500 ֏" },
  { "kind": "pointer", "at": 0.8, "dur": 2.6, "x": 0.62, "y": 0.42, "label": "ՄԵԿ ԿԱԹԻԼ" },
  { "kind": "step",    "at": 0.0, "dur": 3.0, "n": 1, "text": "Կաթեցրու" },
  { "kind": "quote",   "at": 1.0, "dur": 3.0, "text": "...", "author": "Անի" },
  { "kind": "count",   "at": 0.3, "dur": 2.2, "to": 30, "suffix": " ՎՐԿ" },
  { "kind": "name",    "at": 4.0, "dur": 5.0 }
]
```

`pointer` берёт координаты долями кадра: `x: 0.62` — чуть правее центра.
`count` не сочиняет цифры: число должно быть из карточки товара или из отзыва.

## Десять форматов — чем собирается каждый

Закрытый список из таблицы производства. Ниже — что брать под каждый,
чтобы не изобретать сборку заново.

| Формат | Сцены | Накладки | Субтитры |
|---|---|---|---|
| Тест на себе | `hook` → `clip` ×3 → `cta` | `count` на результате | `word-pop` |
| Обзор товара | `hook` → `clip` ×4 | `pointer` на деталях, `offer` в конце | `blur-in` |
| До / после | `hook` → `compare` → `clip` | `count`, `offer` | `zoom-punch` на хуке |
| Польза-гайд | `hook` → `clip` ×3 | `step` 1-2-3 | `typewriter` |
| Находка | `hook` → `clip` ×2 → `cta` | `punch`, `offer` | `word-pop` |
| POV | `hook` (сюжетный) → `clip` ×3 | минимум накладок | `karaoke` |
| Закулисье | `clip` ×4 без хук-титра | `name`, `quote` | `karaoke` |
| Распаковка | `hook` → `clip` ×4 | `pointer`, `count` | `word-pop` |
| Сравнение | `compare` ×2 | `pointer`, `count` | `highlight` |
| Мем | `hook` → `clip` ×2 | `punch` крупно | `zoom-punch` |

**Хук — не заставка, а сцена.** Работает то, что заставляет остановиться:
человек портит вещь, выбрасывает и достаёт обратно, показывает провал.
Товар появляется после этого, а не в первом кадре. Хук занимает 2–3 секунды
и режется из материала, где есть действие, а не из статичного плана.

## Склейки в такт музыке

Если в сценарии задан `bpm`, мост ставит длительности сцен на сетку долей:

```jsonc
{ "bpm": 128, "music": "music.mp3", "beats": [ ... ] }
```

Склейка, попавшая в удар, читается как намеренная, мимо удара — как
оплошность. Зритель не осознаёт ритм, но чувствует собранность.
Темп трека печатает `music.py` при генерации — его и подставлять.

Отключить для отдельного бита: `"snap": false` (нужно, когда длительность
задана жёстко, например под чужой закадровый голос).

## Банк готовых роликов

Каталог материала товара — `products/<товар>/stock-reels/BANK.md`. Там по
каждому ролику: что в кадре, что из него брать, с чем клеить, плюс готовые
связки под типовые сюжеты. **Перед сборкой читать его, а не пересматривать
исходники** — экономит и время, и контекст.

Ключевые слова для поиска новых хуков на стоках — `HOOKS.md` рядом.

## Стили

Восемь. Стиль задаёт палитру, типографику, декор и собственный темп —
код сцен при этом не меняется.

| id | Когда брать |
|---|---|
| `warm-studio` | экспертный тон, разговор в кадре, спокойная подача |
| `bold-orange` | продажа в лоб, хайп, распаковка, находка |
| `clean-minimal` | инструкция, гайд, объяснение без давления |
| `neon-night` | техника, гаджеты, тёмный кадр |
| `fresh-mint` | бытовая химия, чистота, до/после, вода |
| `soft-cream` | косметика, уход, дом — **единственный со светлым фоном и тёмным текстом** |
| `mono-punch` | премиум, сравнение, строгий разбор без украшений |
| `night-gold` | дорогой товар, украшения, подарок |

`soft-cream` берётся, когда кадр сам светлый: белая ванная, постель, кухня.
На таком фоне белый текст остальных стилей пропадает даже с обводкой.

## Темп монтажа

Отдельная ось от внешнего вида: одна и та же палитра нужна и в спокойном
обзоре, и в быстром продающем ролике. Темп управляет скоростью склеек,
зумов и появления титров.

| `pacing` | Длина сцены | Когда |
|---|---|---|
| `calm` | 4–6 сек | обзор, объяснение, дорогой товар |
| `normal` | 3–4.5 сек | рабочий выбор по умолчанию |
| `fast` | 2–3 сек | продающие ролики, распаковка |
| `punch` | 1.2–2.2 сек | мем, хайп, очень короткий хук |

У каждого стиля свой темп по умолчанию, поле `pacing` в спеке его перебивает.
Длина сцены из таблицы — ориентир для плана: при темпе `fast` сцена
на шесть секунд провиснет, даже если материал хороший.

Предпросмотр: композиции `Style-*` и `Caption-*` в `npx remotion studio`.

## Анимация субтитров

Девять видов. Выбирается под материал, а не по привычке.

| Вид | Когда |
|---|---|
| `karaoke` | спокойный разговор, длинные фразы |
| `word-pop` | продающие ролики, динамика — рабочий выбор по умолчанию |
| `blur-in` | премиальная подача, товар в кадре крупно |
| `mask-wipe` | короткие фразы-утверждения |
| `typewriter` | перечисление, инструкция |
| `highlight` | одно слово решает — цена, срок, результат |
| `stagger-up` | список из трёх-четырёх слов |
| `glow` | тёмный кадр, ночь, техника |
| `zoom-punch` | хук и кульминация, самый громкий приём |

Посмотреть все сразу: `npx remotion studio`, композиции `Caption-*`.
Не менять вид внутри одного ролика — это читается как сбой, а не как приём.

## Работа с готовыми чужими рилсами (режим 3)

Банк рилсов товара — это, как правило, **уже смонтированные ролики со вшитыми
субтитрами**, а не сырьё. Стоят они у разных креаторов на разной высоте, так
что одним кропом на весь ролик их не убрать.

Что с этим делать:

1. **Сначала искать чистые клипы** — без текста. Они самые ценные, из них
   строится костяк ролика.
2. Где текст стоит **у самого края** — убирается зумом со сдвигом:
   `"zooms": [[0, 1.4]]` вместе с `"pan": [0, 0.18]` уводит низ кадра
   за границу (положительный Y двигает картинку вниз, то есть съедает низ).
   Обязательно проверить кадром: `.\build.ps1 -Still -Frame N`.

   Считать так: чтобы текст на высоте `h` (долей кадра) ушёл вниз за границу,
   нужно `(h − 0.5) × zoom + 0.5 + pan > 1`, а сам `pan` не должен превышать
   запас `(zoom − 1) / 2`, иначе с другой стороны вылезет пустота. Отсюда
   простое правило: **текст выше 60 % высоты сдвигом уже не убрать** — зум
   получается больше 1.9, и кадр разваливается. Такие клипы не брать.
3. Свои субтитры на такие сцены не ставить: два слоя текста читаются как брак.
   Вместо них — крупный титр в верхнюю треть, туда, где чужого текста нет.
4. **Звук исходника включать**: `"mute": false, "volume": 0.5`. В роликах
   про бытовую химию журчание воды и звук нанесения работают лучше музыки,
   а музыку в таких сценах опустить до 0.05.

Отдельно проверять, что клип вообще про этот товар: в банке часто лежат
съёмки соседних позиций линейки.

## Безопасные зоны

Интерфейс площадки перекрывает часть кадра. Зоны семи сетей — в `src/platforms.ts`,
по умолчанию `multi`: то, что видно везде. Субтитры ставятся от этой границы
автоматически, руками координаты не двигать.

Если ролик идёт только в одну сеть — поставить её в `platform`, освободится
место под текст.

## Звук

1. Речь: `python pipeline/prep.py voice raw.wav --out voice.wav` — фильтр низов,
   чистка шума, компрессия, подъём разборчивости на 3 кГц.
2. Музыка: своя, генерируется `pipeline/music.py`. Настроения: `energetic`,
   `uplifting`, `calm`, `tense`. Громкость 7–8 %, не выше.
3. `duck: true` — музыка проседает под речь. Без этого голос тонет на телефоне.
4. Финал: `python pipeline/prep.py master out/master.mp4 --out out/final.mp4` — −14 LUFS.

**Чужую музыку не брать.** Трек из библиотеки площадки лицензирован только
внутри неё: YouTube заглушит по Content ID, Instagram снимет звук с рилса.

## Озвучка

```bash
# 1. подготовить текст под голос личности
python pipeline/voicer.py prepare script.json --cp CP-01

# 2. сгенерировать в сервисе голосом этой личности, затем довести до монтажа
python pipeline/voicer.py finish script.json --audio voice.mp3 --cp CP-01
```

`finish` делает мастеринг (−16 LUFS, потому что сверху ляжет музыка и на
сведении выйдет −14), сверяет длину озвучки с длиной монтажа и собирает
субтитры **выравниванием**: слова из сценария, тайминги из звука.

Голоса семи личностей — в `factory/personas/CP-0X/`, файл назван по серийнику
телефона. ID клона вписывается в `voice.txt` после клонирования.

Провайдеры, у которых проверено наличие армянского:

| Провайдер | Голоса | Заметки |
|---|---|---|
| Azure Speech | `hy-AM-AnahitNeural` (Ж), `hy-AM-HaykNeural` (М) | дёшево, стабильно, два голоса |
| ElevenLabs v3 | армянский в списке языков | качество выше, дороже |
| VS.AM | синтез и клонирование | армянская платформа |

Семь голосов под семь личностей из двух базовых собираются вариацией
скорости, высоты и стиля. Клонировать голос можно **только с письменного
согласия человека** — это относится и к своим креаторам, и тем более
к чужим роликам из интернета.

### Синтез своими силами — без сервисов и ключей

Черновик, проверку текста, закадровый кусок озвучиваем сами:

```bash
python pipeline/tts.py --file text.md --out public/voice.wav --speed 1.06 --captions src/captions.json
```

Голос `hy_AM-gor-medium` (Piper, ONNX, 64 МБ) лежит в `factory/assets/tts/`,
считает на процессоре быстрее реального времени. Это **восточноармянский** —
тот, на котором говорит Армения.

Чего у нас нет и что проверено: армянских голосов **нет** ни в Edge TTS,
ни в Google TTS, а модели `facebook/mms-tts-hye` не существует —
у Meta только западноармянский `hyw`, с другим произношением.

Три вещи, которые делает `tts.py` и которых нет у сервисов:

1. **Пунктуация под espeak.** Армянский `՞` стоит над ударной гласной
   внутри слова, и espeak читает фразу ровно, без вопроса. Вопрос
   переносится в конец обычным `?`, `՝` становится запятой, `։` — точкой.
2. **Пауза по смыслу.** После вопроса — 0.55 с, между обычными фразами —
   0.30 с. На этих паузах держится ирония; без них текст слипается
   в простыню.
3. **Субтитры прямо из синтеза.** Каждая фраза произносится отдельно,
   поэтому её границы известны точно — точнее, чем даёт выравнивание.
   `align.py` кладёт слова по отрезкам речи и на паузе между фразами
   склеивает конец одного предложения с началом следующего в один блок;
   `--captions` такого не допускает.

### Клонирование голоса — тоже своими силами

Клонирующего TTS с армянским не существует: XTTS, F5, ElevenLabs-клоны
работают по своему списку языков, армянского там нет. Задача решается
в два шага, и второй от языка не зависит вообще:

```bash
python pipeline/tts.py --file text.md --out voice.wav --captions src/captions.json
python pipeline/voiceclone.py --in voice.wav --cp CP-04 --out voice-cp04.wav
python pipeline/voiceclone.py --in voice.wav --all --outdir clones/   # все семеро
```

Конвертер снимает с образца креатора отпечаток голоса и надевает его
на синтезированную речь: слова и тайминги остаются наши, звучание —
человека. Основа — ToneColorConverter из OpenVoice v2 (`assets/voiceclone/`,
код в `C:\Ferma\tools\OpenVoice`). Взят **только конвертер**: его TTS тянет
английскую и китайскую фонемизацию и старые librosa с numpy, которые
сломали бы остальной конвейер.

Что даёт на наших голосах: высота тона попадает в образец с промахом
0.6–3.4%, длительность не меняется ни на кадр — субтитры, собранные под
синтез, подходят клону без пересчёта. Разборчивость по распознаванию
проседает с 69% до 63%: конвертер немного смазывает артикуляцию.
Сила переноса (`--tau`) на это не влияет — пробовали 0.15, 0.30, 0.45,
разница в пределах погрешности, поэтому крутить её смысла нет.

**Образец должен содержать один голос.** В записи CP-03 оказались два
человека — 42% отрезков в мужском регистре, 45% в женском; отпечаток
усреднил обоих и дал голос, которого нет ни у кого, с промахом 39%.
Модуль теперь режет образец на отрезки, меряет высоту тона и оставляет
один регистр (`--register low|high|auto`). Проверять это надо при **каждом**
пополнении банка голосов: образцы нарезаются из роликов, а в кадр попадает
не только сам креатор.

Клонировать голос можно только с согласия человека — у нас оно получено
на всех семерых.

## Замена фона

```bash
python pipeline/matte.py --video raw.mp4 --bg bg.png --out comp.mp4 \
  --grade "0.82,0.76,0.66" --exposure 0.92
```

**Не использовать ffmpeg `chromakey`/`colorkey`** на любительском зелёном фоне —
рвёт лицо, оставляет ореолы. Проверено, даёт брак.

**Ловушка, на которой уже обожглись:** нельзя уменьшать человека (`--scale < 1`),
если в исходнике он обрезан краем кадра. Срез руки уезжает внутрь кадра —
получается «обрубок», и весь ролик выглядит дёшево. Режим `--fit auto`
(по умолчанию) измеряет касание альфы к краям и сам поднимает масштаб.
Чтобы показать больше фона — двигать фон (`--bg-zoom`, `--bg-dx`), а не человека.

## Убрать паузы и лишние подходы

Задача, отдельная от разделения голосов. Голос один, но между фразами человек
молчит: слушает подсказку **в наушнике** (в записи её тогда нет вообще),
собирается с мыслями, начинает дубль заново. В дорожке это полная тишина
по 2–5 секунд.

```bash
python pipeline/tighten.py raw.mp4 --plan runs/plan.json          посмотреть
python pipeline/tighten.py raw.mp4 --out runs/clean.mp4           собрать
python pipeline/tighten.py raw.mp4 --out c.mp4 --take 1.45-22.05 --take 30.7-40.5
```

Порог тишины **абсолютный** (−50 дБ), а не «на N дБ тише пика»: у живой речи
окончание фразы проседает на 15–20 дБ от середины, и по относительному порогу
оно неотличимо от паузы.

`--min-pause` — главная ручка. На 0.45 с материал рассыпался на 15 кусков
по естественным паузам речи; на 0.9 с остались ровно те 5 подходов, которые
человек и делал. Начинать с 0.9 и опускать, только если подходы слипаются.

`--take` берёт заданные куски в заданном порядке — этим убираются дубли,
границы которых видны только по смыслу, а не по тишине.

**Дубли ищутся расшифровкой, а не на слух.** Признак — конец одного подхода
дословно повторяется в начале следующего: человек сбился и начал с
предыдущей фразы. Распознавать надо **каждый подход отдельно**: на длинном
файле whisper склеивает повтор в одно слово (видели «слово» длиной 1.7 с)
и обрывает распознавание на середине, а на слишком коротком куске
начинает выдумывать повторы, которых нет.

## Отделить речь автора от закадровой подсказки

```bash
python pipeline/speechsplit.py raw.mp4 --check        есть ли второй голос
python pipeline/speechsplit.py raw.mp4 --out clean.mp4
python pipeline/speechsplit.py clean.mp4 --verify     контроль
```

Порядок такой и другим быть не может:

1. разделить дорожку на куски речи,
2. разложить куски **на два уровня громкости** — это и есть два говорящих,
3. автор — громкий: он говорит в микрофон, подсказка идёт из динамика,
4. уточнить границы там, где подсказка слиплась с ответом,
5. выбросить повторы,
6. нарезать с микрофейдами 15 мс,
7. проверить: в результате должен остаться **один** уровень.

**Порог берётся из самих данных** (метод Оцу), а не назначается числом:
у разных съёмок расстояние между голосами разное. На живом материале вышло
−31.8 дБ при подсказке −34.1 и авторе −25.7, разрыв 8.5 дБ.

**Из пары одинаковых соседних реплик всегда оставляем вторую.** Два разных
случая дают одну картину: подсказка прозвучала и автор повторил, либо автор
сбился и сказал заново. В обоих нужен второй кусок. Сравнение текста
нечёткое — распознавание армянского пишет одну фразу по-разному, и сверка
по первым буквам такую пару не ловит.

### Четыре ошибки, каждая оставляет диктора в ролике

Все четыре сделаны на живом материале, прежде чем метод устоялся.

| Ошибка | Что происходит |
|---|---|
| **Резать паузы вместо разделения голосов** | пауза не знает, кто говорит: подсказка и автор для неё одинаково «звук». Убирая тишину, склеиваешь их вместе |
| **Верить правой границе куска** | хвост затягивает паузу и прихватывает начало следующей реплики диктора — **именно так он и остаётся в ролике** |
| **Брать порог наугад** | −50 дБ: подсказка считается звуком и остаётся. −20 дБ: срезаются тихие окончания слов автора |
| **Судить по высоте голоса** | подсказку часто пишет сам автор или похожий голос. На живом материале тон отличался на 17 Гц, проверка сказала «один человек», а голосов было два |

Четвёртая — моя собственная: после случая, где нарезка порвала чистую
запись, правило «громкость обманывает» стало единственным вместо
дополнительного. **Решает громкость, тон только уточняет.**

### Диктор в середине куска — самый коварный случай

Если автор начал повторять почти без паузы, подсказка **слипается с его
речью в один кусок** и обрезка краёв её не берёт: диктор сидит в середине.
Так он и попал в готовый ролик на 14-й секунде — снаружи кусок выглядел
речью автора.

Поэтому внутри каждого куска ищутся **все** участки автора списком
(`author_regions`), а между ними классифицируются провалы. Провал — это
диктор, если он длиннее 0.5 с, **и** на уровне голоса (медиана громче
−48 дБ), **и** почти без громких окон (<25%). Все три условия сразу:
по одному уровню решать нельзя — тихие окончания слов автора живут на
уровне диктора; по одной длине нельзя — провал живой речи размывается
скользящим средним и выглядит длинным.

Громкое ударное слово диктора **по уровню неотличимо от слова автора** —
на живом материале оба дали −24 дБ. Различает их окружение: всплеск диктора
сидит между двумя дикторскими провалами (каждый весомый, от 0.2 с),
а короткий кусок автора граничит со своей же речью или тишиной.

### Хвост слова ведётся по затуханию, а не по порогу

Порог «речь/тишина» отсекает последний согласный — он тише порога, и слово
обрывается за миллисекунды до конца. Хвост продлевается, пока звук затухает
(допуск на дребезг фрикативных 3 дБ — жёсткий допуск рвал их), и
останавливается на чётком подъёме уровня: это уже заход чужой реплики.
К тишине хвост дополняется запасом 0.18 с, к диктору — нет.

### Две величины, зажатые с обеих сторон

**Сшивка провалов (`GAP_FILL`, 0.12 с).** Больше — подсказка слипается
с ответом в один кусок, и повтор остаётся внутри него. Меньше — фраза
рассыпается на слоги.

**Поиск края слипшегося куска.** Искать паузу *ниже* уровня подсказки
бесполезно: подсказка сама громче такой границы, обрезка проходит мимо неё
и диктор остаётся. Брать порог между голосами как границу паузы тоже нельзя:
внутри живой речи полно мгновенных провалов до него, фраза режется на
обрывки по 0.7 с. Работает третье — искать **последний и первый громкие
участки** скользящим окном 0.3 с.

### Контроль обязателен

```bash
python pipeline/speechsplit.py clean.mp4 --verify
```

Проверять надо программно: тихий диктор на фоне легко не заметить на слух,
особенно если слушаешь не в наушниках. В чистовике разброс громкости между
кусками падает до 1.5–2 дБ против 8.5 в исходнике. Осталось два уровня —
где-то не уточнена граница или порог взят неверно.

Если подсказка звучит **одновременно** с автором (наушник фонит в микрофон),
нарезкой её не убрать: нужно разделение источников, например Audio Isolation
у ElevenLabs.


```bash
python pipeline/speechsplit.py raw.mov --edl runs/edl.json   # разбор
python pipeline/speechsplit.py raw.mov --out clean.mp4       # сразу чистовик
```

**Резать по тишине нельзя.** Креатор повторяет за подсказкой почти без паузы,
и любая нарезка по тишине оставляет их в одном куске — в ролике будет слышно
обе реплики. Поэтому разбор идёт **по окнам 0.1 секунды**: каждое окно
относится к автору или к подсказке по громкости, и участки собираются заново.
Короткие провалы внутри фразы (дыхание, смычки согласных) затягиваются,
островки короче 0.35 секунды выбрасываются.

Скрипт делает три проверки разом: громкость (подсказка тише живой речи
на 10–12 dB), высоту голоса (подсказка часто чужим голосом) и длину куска.
Уровень автора берётся по верхней части распределения, а не по среднему —
среднее утягивают вниз длинные тихие подсказки.

**Эталон результата:** в правильно смонтированном ролике речь идёт сплошным
потоком, без пауз. Если после сборки `speechsplit.py` находит в нём больше
одного куска речи — значит подсказка или паузы остались, надо пересобирать.

**Резать слишком плотно тоже нельзя.** Проверено на боевом материале: при
запасе 0.06 с по краям куски начинались с середины слова, речь становилась
рваной, и её переставала разбирать даже модель распознавания — 15 слов
вместо 54. Рабочие значения в `speechsplit.py`: запас 0.14 с, склейка пауз
до 0.28 с. **Проверка простая:** прогони чистовик через `transcribe.py` —
если слов стало заметно меньше, чем в исходнике, нарезка съела речь.

Куски, которые тише, но ненамного, помечаются **спорно** — их смотрят глазами:
у подсказки рот закрыт, это решающий признак.

Замерено на реальном сырье: из 366 секунд съёмки осталось 88 секунд речи
автора, 35 кусков подсказки выброшено.

### Нарезка говорящей головы на сцены

**Руками таймкоды не задавать.** Склейка, поставленная «на глаз», попадает
в середину слова, и монтаж читается как грубый. Границы берутся из субтитров:

```bash
python pipeline/autospec.py clip.mp4 --captions src/captions.json --max 30
```

Скрипт ставит склейки **в паузы между фразами**, собирает сцены по 2.5–6 секунд
и расставляет зумы через одну. Тогда jump-cut выглядит приёмом, а не ошибкой.

### Как это выглядит в разборе

Три независимые проверки, совпадение = уверенность:

1. **Громкость** — подсказка тише на 10–12 dB (звучит из динамика).
   `pipeline/scan.py audio` даёт карту громкости по времени.
2. **Тишина с порогом выше уровня подсказки** (`-34 dB`) — точные границы фраз.
3. **Губы на кадре** — вырезать кадр в момент реплики: у подсказки рот закрыт.
   Решающий тест.

Дальше: план только из сегментов автора, выкинуть фальстарты (та же фраза,
повторённая полнее) и техническую болтовню в конце.

**Громкости одной мало:** фальстарт звучит ровно так же, как удачный дубль.
Какой из двух оставить — решается по тексту, не по уровню сигнала.

## Расшифровка речи — что работает, а что нет

Замерено на банке, а не взято из документации:

| Язык | Модель | Ошибок | Вывод |
|---|---|---|---|
| Русский | `small` | ~1 слово из 50 | Годится и в субтитры, и чтобы вытащить текст |
| Армянский | `small` | бессмыслица | Не использовать |
| Армянский | `large-v3` | половина слов | Смысл верный, буква нет |
| Армянский | `large-v3` + подсказка | ~4 слова из 30 | Черновик, нужна вычитка |

**Подсказка обязательна.** Без списка слов модель пишет бренд как слышит:
`Դյուրին` превращается в `Չուրին`. Словарь лежит в `transcribe.py`
(`DEFAULT_HINT`) и пополняется при новых товарах, свой можно передать
ключом `--hint`.

Отсюда правило: **если текст реплики известен заранее, он всегда надёжнее
расшифровки.** Армянские субтитры строим из сценария (`script2spec.py`).
Расшифровка нужна там, где текста нет: чужой ролик, съёмка без сценария,
русская линия для ВК и Одноклассников — там она отрабатывает начисто.

## Субтитры на армянском — как делать правильно

Распознавание армянского ошибается слишком часто, чтобы пускать его в кадр.
Но нам оно и не нужно: **текст реплик уже есть в сценарии**, написанный
носителем. От звука требуется только одно — когда что было сказано.

```bash
python pipeline/align.py voice.wav --script script.json --out src/captions.json
```

`align.py` берёт у модели **только тайминги**, а слова подставляет из
сценария. Модель может услышать «Չուրին» вместо «Դյուրին» — в субтитры
это не попадёт никогда, потому что слова туда идут наши.

Так закрывается вся проблема армянских субтитров: буква из сценария,
время из звука.

## Уникализация — варианты одного ролика

```bash
python pipeline/uniquify.py master.mp4 --out-dir variants --count 4 --report var.json
```

Один вариант — одно отличие, и оно записано в отчёт. Скрипт предупредит,
если у варианта совпала длительность с мастером: для площадки это самый
заметный признак дубля.

**Зеркалить нельзя** — в кадре текст, логотип и упаковка, зеркальные
надписи видно сразу.

## Слова, которые проверил владелец

Правки носителя языка. Они важнее словаря: текст читают армяне, и неточное
слово выдаёт машинный перевод сразу.

| Не писать | Писать | О чём |
|---|---|---|
| `բիծ` | `հետք` · `լաքա` | след, пятно от еды, грязи, вина |

Список пополняется после каждой правки владельца. Новое слово сюда — до того,
как оно уйдёт в следующий ролик.

## Субтитры на армянском

Текст берётся **из сценария**, а не распознаётся с нуля: распознавание
восточноармянского даёт ошибки, которые придётся вычитывать руками на каждом
ролике. Если текст известен — нужны только тайминги.

Блоки по 5–6 слов, разрыв больше 0.55 с или конец предложения начинают новый
блок. Формат `src/captions.json`: `[{start, end, words:[{t,s,e}]}]`.

Шрифты: `Montserrat-Black` (лат+кир) · `NotoArm` (лат+арм) · `Anton` (латиница).
Системные SF Pro / Georgia армянский НЕ рендерят, Anton не знает кириллицы.
Выбор — по полю `lang`.

## Контроль качества

`python pipeline/qc.py out/master.mp4` проверяет числами: 1080×1920 · 24–60 fps ·
15–40 сек · −14 ± 1.5 LUFS · нет пауз длиннее 1.5 с · нет чёрных и замерших
кадров · есть звуковая дорожка.

Глазами после этого — 4–5 кадров: артефакты матирования, ореолы, **срезы рук**,
перекрытия текста, читается ли субтитр на светлом фоне.

## Что движок делает сам — и о чём надо знать

- **Субтитры скрываются на CTA и на хуке с титром.** Там уже стоит крупный
  текст, второй слой поверх читается как ошибка сборки. Переопределяется
  полем `captions: true` на сцене, выключается везде — `captions: false`.
- **Накладки уходят плавно**, за шесть кадров до конца своей длительности.
  Поэтому `dur` накладки надо задавать честно, а не «с запасом».
- **Счётчик `count`** набирает число за первые две трети показа и стоит
  до конца — отдельно скорость задавать не нужно.
- **Бейдж и лейблы стоят слева сверху**, под безопасной границей. Справа
  внизу их ставить нельзя: там колонка кнопок площадки.
- **Артикул никогда не касается субтитров.** Его отступ считается от реальной
  высоты блока субтитров (`captionBlockHeight`), а не задаётся числом:
  при крупном шрифте любое фиксированное значение рано или поздно даёт
  наложение, и цифры пропадают под текстом. Это правило жёсткое —
  подбирать отступ на глаз нельзя.
- **Артикул попадает в ролик и при автосборке.** `autospec.py` строит спеку
  из говорящей головы и раньше собирал её вообще без финальной сцены —
  ролик уезжал без артикула, а все проверки на нём проходили. Теперь финал
  добавляется по `--sku`, время под него **отрезается от последней сцены**,
  а не удлиняет ролик: сумма длительностей должна остаться равной длине речи.
- **Артикул целиком помещается в кадр.** Размер шрифта подгоняется
  `fitFontSize` по измеренной ширине строки, а не берётся постоянным:
  на 56 пунктах армянская строка «WB Արտիկուլ։ 287963132» вылезала за края
  и крайние цифры срезало. Оценка «символов × коэффициент» тут не годится —
  армянские буквы шире латиницы, мерить надо настоящим шрифтом кадра.
  Формат строки один и в движке, и в раскатке на семь личностей.

## Грабли

- Remotion не читает mp4 с mp3-звуком внутри («Assertion failed») — `prep.py shots`
  приводит всё к h264+aac, поэтому исходники всегда прогонять через него.
- Кадр без полного рендера: `npx remotion still Reel --frame=120 out/frame.png`.
- Макет нарисован в координатах 720×1280 и масштабируется в 1080×1920 —
  размеры в компонентах менять не нужно, они уже в этой системе.
- Сумма `sec` всех сцен должна совпадать с длиной озвучки, иначе последняя
  сцена оборвётся или повиснет замершим кадром (qc это ловит).
- Громкость приводится **в два прохода** — `prep.py master` так и делает.
  Однопроходный `loudnorm` промахивается мимо цели на 2–3 LUFS, и проверка
  показывает брак при формально отработавшем фильтре.
- Мерить громкость нужно **вместе с компрессором**, той же цепочкой, что
  пойдёт в дело. Замер по чистому исходнику даёт `loudnorm` неверную точку
  отсчёта: он считает вход громче, чем тот есть после компрессии, и уводит
  результат вниз. Ролик с озвучкой так получил −17.4 LUFS вместо −14 при
  том, что до мастеринга был −13.
- Статичная финальная сцена — не мелочь: qc ловит её как замерший кадр,
  а зритель уходит до призыва. Любой статичный кадр дольше двух секунд
  должен получить медленный наезд.
- Сцена `compare`, собранная из двух стоп-кадров, тоже даёт замирание:
  после того как граница доехала, в кадре не остаётся движения. Брать
  для неё куски, где что-то происходит — руки, ткань, вода.

Связано: скилл `lipsync` (синхронизация губ), плейбук вики `сценарии-и-хуки`.
